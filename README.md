# آواتار جدید — دستیار صوتی فارسی با آواتار

بازدیدکننده دکمهٔ «گفتگو» را می‌زند و **با صدا** سؤال می‌پرسد؛ آواتار با **فارسی روان** و **حرکت لب هماهنگ** جواب می‌دهد و دوباره گوش می‌کند. همهٔ سرویس‌ها و کلیدهای API از **پنل مدیریت** مدیریت می‌شوند، بدون تغییر کد.

این پروژه از تجربهٔ پروژه‌های قبلی (راوی‌استان، زایر، Persian Voice Companion) ساخته شده و مشکلات تکرارشدهٔ آن‌ها را از ریشه حل می‌کند:

| مشکل در پروژه‌های قبلی | راه‌حل این پروژه |
|---|---|
| مغز و صدای فارسی دست سرویس آواتار بود (HeyGen/D-ID/Beyond) و فارسی را خوب نمی‌فهمید | گفتار→متن، پاسخ و صدای فارسی در سرور خودمان ساخته می‌شود؛ سرویس آواتار فقط لب می‌زند |
| چند سرویس جدا روی لیارا (API، worker، agent، web) و خطای ۵۰۲ | **یک سرویس** Next.js + یک PostgreSQL |
| سرویس‌های خارجی از سرور ایران در دسترس نیستند | پروکسی خروجی قابل تنظیم در پنل + پشتیبانی از درگاه‌های ایرانی سازگار با OpenAI |
| وابستگی به Supabase/Lovable | PostgreSQL معمولی؛ روی لیارا یا هر میزبان دیگر |
| نیامدن تصویر آواتار | «آواتار داخلی» بدون هیچ سرویس خارجی که همیشه کار می‌کند |

---

## جریان یک نوبت گفتگو

```text
مرورگر                                   سرور (Next.js)                           سرویس‌ها
───────                                  ──────────────                           ────────
میکروفون + تشخیص شروع/پایان صحبت (VAD)
   │ فایل WAV
   └──────────────► /api/turn ──► گفتار به متن (STT) ────────────────► OpenAI / Azure / ElevenLabs / درگاه ایرانی
                               ──► جست‌وجو در پایگاه دانش
                               ──► مدل پاسخ (LLM، جریانی) ─────────────► OpenAI / Claude / Gemini / درگاه ایرانی
                               ──► هر جمله → صدای فارسی (TTS) ────────► Azure / ElevenLabs / OpenAI
   ◄──── رویدادهای جریانی: متن + صدای هر جمله (PCM 24kHz)
آواتار: پخش صدا + حرکت لب
   ├─ داخلی: حرکت لب از روی شدت صدا (بدون سرویس خارجی)
   ├─ Simli: صدا به سرویس فرستاده می‌شود، ویدیوی لب‌خوانی برمی‌گردد
   └─ HeyGen LiveAvatar (حالت LITE): همین‌طور
```

آواتار **بعد از آماده‌شدن جملهٔ اول** شروع به صحبت می‌کند، نه بعد از کل پاسخ؛ بنابراین تأخیر کم است.

## اجرای محلی

پیش‌نیاز: Node.js 20.18 یا جدیدتر، PostgreSQL 13 یا جدیدتر.

```sh
npm install
cp .env.example .env        # مقادیر را پر کنید (پایین را ببینید)
npm run dev                 # http://localhost:3000
```

جدول‌ها هنگام اجرای سرور **خودکار** ساخته می‌شوند. اگر `ADMIN_EMAIL` و `ADMIN_PASSWORD` در `.env` باشند و هنوز مدیری وجود نداشته باشد، اولین مدیر ساخته می‌شود. روش دیگر:

```sh
npm run admin:create        # ساخت مدیر یا بازنشانی گذرواژهٔ فراموش‌شده
```

### متغیرهای محیطی

| متغیر | توضیح |
|---|---|
| `DATABASE_URL` | نشانی PostgreSQL |
| `SESSION_SECRET` | رشتهٔ تصادفی حداقل ۳۲ نویسه (`openssl rand -hex 32`) |
| `ENCRYPTION_KEY` | رشتهٔ تصادفی حداقل ۳۲ نویسه؛ کلیدهای API با آن رمزنگاری می‌شوند. **تغییرش یعنی باید همهٔ کلیدها را دوباره وارد کنید.** نسخهٔ امنی از آن نگه دارید. |
| `ADMIN_EMAIL`، `ADMIN_PASSWORD` | اختیاری؛ ساخت اولین مدیر. بعد از ورود، گذرواژه را از متغیرها حذف کنید. |
| `DATABASE_SSL` | فقط برای پایگاه دادهٔ محلی بدون TLS: `false` |
| `ENABLE_MOCK_PROVIDERS` | فقط توسعه: `1` سرویس «آزمایشی» بی‌هزینه را فعال می‌کند |

کلیدهای سرویس‌ها (OpenAI، Azure و…) **در متغیر محیطی قرار نمی‌گیرند**؛ از پنل مدیریت وارد می‌شوند.

---

## استقرار روی لیارا

1. یک **PostgreSQL** در لیارا بسازید و نشانی اتصال آن را بردارید.
2. یک برنامهٔ **Docker** بسازید (پورت ۳۰۰۰). فایل‌های `Dockerfile` و `liara.json` آماده‌اند.
3. در بخش متغیرهای محیطی برنامه: `DATABASE_URL`، `SESSION_SECRET`، `ENCRYPTION_KEY`، `ADMIN_EMAIL`، `ADMIN_PASSWORD`.
4. استقرار: `liara deploy` از پوشهٔ پروژه (یا اتصال مخزن گیت‌هاب در کنسول لیارا).
5. پس از بالا آمدن: `https://<دامنه>/admin` ← ورود ← ادامه در بخش بعد. سپس `ADMIN_PASSWORD` را از متغیرها حذف کنید.

سلامت برنامه از `/api/health` بررسی می‌شود (اتصال پایگاه داده). میکروفون فقط روی **https** کار می‌کند؛ دامنهٔ لیارا https دارد.

## راه‌اندازی از پنل مدیریت

در صفحهٔ اصلی، آیکون چرخ‌دندهٔ کم‌رنگ گوشهٔ صفحه به `/admin` می‌رود. تب «نمای کلی» یک فهرست راه‌اندازی دارد.

### ۱. سرویس‌ها و کلیدها
«افزودن سرویس» ← یکی از گزینه‌های آماده ← کلید API ← ذخیره ← **آزمون اتصال**.

| سرویس | برای | نکته |
|---|---|---|
| **Azure Speech** | صدای فارسی و گفتار به متن | بهترین صدای فارسی: `fa-IR-DilaraNeural` (زن)، `fa-IR-FaridNeural` (مرد). منطقه (region) را وارد کنید. |
| **OpenAI** | مدل پاسخ، گفتار به متن (`gpt-4o-transcribe`)، صدا، بردارسازی | از سرور ایران فقط با پروکسی |
| **AvalAI / GapGPT** | همان قابلیت‌های OpenAI از داخل ایران بدون پروکسی | نشانی پایه را با مستندات همان سرویس تطبیق دهید |
| **Anthropic Claude** | مدل پاسخ | پیش‌فرض `claude-opus-5`؛ برای پاسخ سریع‌تر «عمق فکر: کم» |
| **Gemini / OpenRouter / Groq** | مدل پاسخ (Groq: گفتار به متن سریع) | سازگار با OpenAI |
| **ElevenLabs** | صدا و گفتار به متن | برای فارسی مدل `eleven_multilingual_v2` و شناسهٔ صدایی که فارسی را خوب می‌خواند |
| **Simli / HeyGen LiveAvatar** | آواتار ویدیویی زنده | اختیاری |

### ۲. مغز و صدا
برای هر قابلیت یک **سرویس اصلی** و یک **سرویس پشتیبان** انتخاب کنید؛ اگر اصلی خطا بدهد، پشتیبان خودکار استفاده می‌شود. پس از ذخیره، دکمهٔ «شنیدن» صدای فارسی را همان‌جا پخش می‌کند.

### ۳. آواتار
- **داخلی (پیش‌فرض):** بدون هزینه و بدون سرویس خارجی. چهار نسخه از یک تصویر با قاب یکسان بارگذاری کنید که فقط دهان در آن‌ها فرق دارد (بسته، کمی باز، گرد، باز)؛ مثلاً با ویرایش تصویر به‌کمک هوش مصنوعی. سپس کادر دهان را روی لب‌ها تنظیم و با «حرکت» بررسی کنید. بدون تصویر، یک چهرهٔ طراحی‌شده نمایش داده می‌شود.
- **Simli:** کلید Simli + Face ID.
- **HeyGen LiveAvatar:** کلید LiveAvatar + شناسهٔ آواتار.

> ویدیوی Simli و LiveAvatar مستقیم از مرورگر بازدیدکننده دریافت می‌شود؛ کاربران داخل ایران ممکن است بدون فیلترشکن به آن دسترسی نداشته باشند. آواتار داخلی این مشکل را ندارد.

### ۴. شخصیت و رفتار
نام، دستورالعمل (پرامپت)، خوشامدگویی، حالت پایگاه دانش (ترجیحی / فقط پایگاه دانش / خاموش)، حساسیت شنیدن، مکث پایان جمله، اجازهٔ قطع صحبت آواتار، و سقف مصرف.

### ۵. پایگاه دانش
PDF، TXT، MD یا متن دستی. اگر سرویس بردارسازی انتخاب شده باشد جست‌وجو معنایی است؛ وگرنه کلیدواژه‌ای. PDF اسکن‌شده (تصویری) متن ندارد.

### ۶. شبکه و امنیت
**پروکسی خروجی** برای سرور داخل ایران: نشانی `http://user:pass@host:port` ← ذخیره ← «آزمون دسترسی». سپس در هر سرویس خارجی گزینهٔ «استفاده از پروکسی» را روشن کنید. مدیران و تغییر گذرواژه هم اینجاست.

## امنیت

- صفحهٔ اصلی عمومی و بدون ثبت‌نام است؛ هر بازدیدکننده یک کوکی امضاشده می‌گیرد که فقط مالکیت گفتگوی خودش را ثابت می‌کند.
- ثبت‌نام عمومی و حساب پیش‌فرض وجود ندارد. همهٔ مسیرهای `/api/admin/*` نشست مدیر و بررسی مبدأ (Origin) دارند. کوکی مدیر `HttpOnly` و `SameSite=Strict` است.
- کلیدهای API با AES-256-GCM رمزنگاری می‌شوند و هرگز به مرورگر برنمی‌گردند (فقط نسخهٔ پوشانده، مثل `sk-••••abcd`).
- سقف درخواست برای هر بازدیدکننده، هر IP و کل سامانه؛ ورود مدیر ۱۰ تلاش در ۱۵ دقیقه.
- تاریخچهٔ گفتگو در سرور بازسازی می‌شود، نه از مرورگر؛ متن پایگاه دانش به‌عنوان «داده» به مدل داده می‌شود نه «دستور».
- صدای خام کاربر ذخیره نمی‌شود؛ فقط متن گفتگوها برای مرور مدیر.

## آزمون

```sh
npm run typecheck
npm run lint
npm run build
# با سرور در حال اجرا و ENABLE_MOCK_PROVIDERS=1:
BASE_URL=http://localhost:3000 ADMIN_EMAIL=... ADMIN_PASSWORD=... npm run test:e2e
```

`test:e2e` یک سرویس آزمایشی می‌سازد، همهٔ قابلیت‌ها را به آن وصل می‌کند و یک نوبت صوتی و یک نوبت متنی را کامل بررسی می‌کند (به‌همراه ورود، پوشاندن کلید، جلوگیری از درخواست بین‌سایتی و مالکیت گفتگو).

### وضعیت آزمون‌ها

| بخش | وضعیت |
|---|---|
| کل مسیر گفتگو با سرویس آزمایشی (API) | ✅ آزموده شد |
| مرورگر واقعی (Chromium) با میکروفون مجازی: تشخیص صحبت، ارسال، پاسخ، حرکت لب، بازگشت به شنیدن | ✅ آزموده شد |
| هم‌ترازی تصاویر دهان آواتار داخلی | ✅ آزموده شد |
| فراخوانی واقعی OpenAI، Azure، ElevenLabs، Anthropic | ⚠️ طبق مستندات رسمی نوشته شده؛ با کلید واقعی آزموده نشده |
| Simli و HeyGen LiveAvatar | ⚠️ طبق SDK رسمی نوشته شده؛ با کلید واقعی آزموده نشده. نشانی دریافت توکن LiveAvatar (`/v1/sessions/token`، حالت LITE) باید با حساب واقعی تأیید شود. |

پس از واردکردن کلیدهای واقعی، «آزمون اتصال» هر سرویس و «شنیدن» در تب «مغز و صدا» اولین بررسی‌ها هستند.
